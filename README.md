# AI电商自动化工作流系统

> 抖音电商选品→素材→投流→出单→复盘全流程自动化原型
> AI全栈开发工程师测试题 | 30天从0到1完成

## 项目简介

这是一个"小而完整、能运行、可继续迭代"的内部提效原型，围绕抖音电商真实业务流程设计：

1. **选品与素材**：选品→确认商品→确定佣金→搜集素材
2. **素材生产**：混剪→去重→前端挂车发布/千川上传
3. **投流测试**：创建投流计划→数据回填→效果监测
4. **出单放量**：出单触发→AI钩子精剪→百单/千单放量
5. **复盘闭环**：数据复盘→判断继续/停测/加量→重新选品

## 快速开始

### 1. 环境准备

```bash
# 安装依赖
pip install -r requirements.txt
```

在项目根目录创建 `.env` 文件，配置通义千问（阿里云百炼/DashScope）的 API Key：

```
DASHSCOPE_API_KEY=你的API Key
```

### 2. 初始化数据库

```bash
python run.py init
```

这会创建数据库表并插入测试题给出的样例数据（5个商品、6条视频、6个投流计划）。

### 3. 启动服务

#### 方式一：启动前端界面（推荐，包含所有功能）

```bash
python run.py ui
```

访问 http://localhost:8501

#### 方式二：启动API后端

```bash
python run.py api
```

访问 http://localhost:8000/docs 查看接口文档

#### 方式三：命令行和Agent对话

```bash
python run.py agent
```

### 4. 运行测试

```bash
python run.py test
```

### 5. 运行全流程演示

```bash
python run.py demo
```

## 核心功能

### 任务1：数据结构与状态设计（15分）

4类数据对象，完整状态流转：

- **商品表**：商品ID、商品名、类目、佣金、负责人、选品状态、累计订单、阶段
- **素材/视频表**：视频ID、商品ID、素材来源、混剪状态、去重状态、发布标记、订单数、ROI
- **投流计划表**：计划ID、商品ID、视频ID、计划状态、消耗、订单数、ROI、异常标记
- **任务/复盘表**：任务ID、触发来源、任务类型、负责人、优先级、状态、触发原因、复盘结论

状态流转：待选品→已确认→素材搜集→混剪→去重通过→前端已发布/千川待上传→投流测试→出单→AI钩子精剪→放量→百单/千单→复盘→再选品

### 任务2：核心自动化工作流（30分）

6个必做触发点：

| 触发点 | 名称 | 规则 |
|--------|------|------|
| A | 商品确认 | 商品已确认+有佣金→自动创建素材任务；无佣金→阻断提醒 |
| B | 去重完成 | 第1条通过→前端挂车发布；其余→千川上传/建计划 |
| C | 出单触发 | 订单从0→≥1→标记出单素材+创建AI精剪任务（幂等） |
| D | 放量分级 | 累计≥100单→百单阶段；≥1000单→千单阶段+放量任务 |
| E | 无效素材 | 消耗≥300且0单，或测试≥72小时且0单→停测任务 |
| F | 日/批次复盘 | 汇总继续/精剪/放量/停测，输出结构化复盘结果 |

### 任务3：Agent数智员工（30分）

"素材与投流复盘数智员工"，能力包括：

- **能读数据**：从4张表实时查询，不写死答案
- **4类必答问题**：
  1. 今天哪些视频已出单？
  2. 哪些需要立即进入AI钩子精剪？
  3. 哪些商品已进入百单/千单阶段？
  4. 哪些商品/素材应停测、重测或继续放量？
- **给依据**：回答引用商品ID/视频ID、关键数据和触发规则
- **执行动作**：创建AI精剪任务、创建停测任务、写回复盘结论
- **人工确认**：高风险动作（停测、批量改状态）需要确认
- **边界控制**：不猜测、不删除、不越权

### 任务4：工程可靠性（15分）

- **防重复**：每个触发点有去重键，幂等保护，重复触发不重复创建任务
- **异常处理**：缺佣金阻断、查询不存在报错、工具调用失败有提示
- **配置化**：所有阈值在 `config/settings.yaml` 中配置，无需改代码
- **可追踪**：触发记录表、操作日志表，关键动作有记录
- **自定义代码**：自研状态机、工作流引擎、Agent工具系统

### 任务5：演示与现场改动（10分）

- 可运行原型：前端界面+API后端+命令行
- 录屏脚本：6-8分钟演示流程
- README：架构、启动方式、配置、已知限制
- 现场改动：配置化设计，改阈值只需修改YAML文件

## 关键配置

所有配置在 `config/settings.yaml` 中：

```yaml
# 放量阈值
thresholds:
  hundred_orders: 100      # 百单阈值
  thousand_orders: 1000    # 千单阈值

# 停测规则
stop_test_rules:
  by_cost:
    max_cost: 300          # 消耗超过300元
    min_orders: 0          # 且订单为0
  by_duration:
    max_hours: 72          # 测试超过72小时
    min_orders: 0          # 且订单为0

# 出单判定
order_trigger:
  min_orders: 1            # 订单达到1单视为出单
```

## 已知限制

1. **外部平台接口为模拟**：抖音/千川的上传、投流等动作使用模拟接口，实际接入需要替换为真实API
2. **定时任务需手动触发**：日复盘等定时任务需要手动触发，可接入APScheduler实现自动定时
3. **单用户系统**：未实现多用户权限管理
4. **SQLite并发限制**：SQLite适合原型和小规模使用，高并发需替换为PostgreSQL/MySQL
